# Redis Key Registry

Redis may hold only state that can be rebuilt from PostgreSQL, bundle storage
or the secrets manager, or state whose loss costs a retry. This page lists what
the platform actually writes to Redis, so that rule can be checked family by
family. It is maintained with the code: a change that adds, removes or changes a
Redis key family, its TTL or what it holds updates its row here.

Read at:

- KDCube `409c4030832031abd7c299a7439f57884f0b4893` (this repository);
- App Ecosystem `c23197780b40d6e40dcb4b44fa4073d8c70f0531`, for the Connection
  Hub package and app, whose Redis writers live there.

Applications and bundles that write their own Redis keys list them in their own
documentation; this page covers the platform and Connection Hub.

## Classes

Each row carries one class. The test is what a loss *or a rollback to an older
Redis snapshot* does, not whether the key has a TTL. A TTL alone does not make a
record non-durable.

| Class | Meaning |
|---|---|
| cache | A named durable source (PostgreSQL, bundle storage, the secrets manager) rebuilds it, and an older snapshot cannot be accepted as current authority. |
| retry-cost | Loss only aborts work in progress and makes its caller retry: sign in again, re-run, re-acquire a lock, re-fetch or re-compute. A rollback cannot revive a consumed operation. |
| durable | Loss or rollback changes a still-valid login, credential, grant, revocation, replay decision, enforced budget, or loses accepted work or records held nowhere else. |

Some families are durable only in one mode. They name it:

- **Redis-source mode** is the authority backend `redis-migration-source`, the
  default when `auth.sessions.authority.backend` is absent
  (`apps/chat/sdk/config.py:1808-1819`). **PostgreSQL mode** is
  `backend: postgresql` with an activated `generation_id`
  ([Move Runtime Authority To PostgreSQL](../recipes/operations/move-authority-to-postgresql-README.md)).
- **Legacy mode** is a bundle registry with no descriptor store.

- KDCube paths are relative to `app/ai-app/src/kdcube-ai-app/kdcube_ai_app/`
  unless they start with `kdcube_cli/`.
- App Ecosystem paths use `$CH` = `products/connection-hub/packages/connection-hub/src/connection_hub`,
  `$DC` = `$CH/delegated_credentials`, `EP` =

## Authority mode

The authority backend decides which session and credential families Redis
holds. Binding is in `auth/session_authority_runtime.py`: Redis-source mode at
`:112-115`, PostgreSQL mode at `:217-316` behind
`require_activated(generation_id, families)` (`:288-291`).

| Families | Redis-source mode | PostgreSQL mode |
|---|---|---|
| P1 platform sessions, P2 session index | written; P1 is the session authority | not written; old keys stay until removed, and only the migration reads them (`auth/migration/redis_source.py:177-219`) |
| P3 bundle-session user, P4 user version | written with no TTL; **durable** | not written; `PostgresBundleSessionStore` is the authority |
| P5 bundle session, P6 user-sessions, P7 user lock | written; P5 is **durable** (a restored row revives a logged-out session) | not written; P7 becomes `pg_advisory_xact_lock` (`auth/bundle/session_issuance_store.py:141, 240`) |
| P8, P9 bundle-session projection; P10, P11 platform-session projection | not written | written as generation-scoped caches of PostgreSQL, fence-checked on every positive hit |
| A1 OAuth clients, A2 refresh chains, A3 access bindings, A4 Card handles | written; the only copy, **durable** | not written; the PostgreSQL authority store holds them |
| A5 admission replay nonce | written; **durable** replay fence | not written; PostgreSQL `replay_claims` |

The table describes `auth.sessions.platform.backend: authority` (the default).
With `auth.sessions.authority.backend: postgresql` and
`auth.sessions.platform.backend: redis`, P1 and P2 use their existing
Redis TTL lane. P10 and P11 are
then not written; P8 and P9 remain fenced PostgreSQL projections. The three
bundle families and their issuance ledger remain PostgreSQL-authoritative,
and their activation receipt need not include `platform_sessions`. Other
families and Connection Hub's authority selection are unchanged. See the
[session storage descriptor contract](../configuration/assembly-descriptor-README.md#session-authority-storage)
for the restart boundary and existing-row behavior.

`auth/migration/redis_source.py:29-34` names P1 (without `index:*`), P3, P4 and
P5 as the families a cutover carries, and App Ecosystem's reset source carries
A1 to A5.

## Durable families

These rows hold state that no other store has. Removing them from Redis, or
accepting them as durable, is a separate decision for each; this page records
the finding.

In every mode:

- **2.24** `{t}:{p}:kdcube:config:gateway:current`: admin gateway edits are saved only here.
- **2.39** `kdcube:economics:rl:*`: per-user quota usage, with no PostgreSQL copy.
- **3.1, 3.2** the chat prompt queue and its in-flight list: an accepted prompt
  exists only here until its turn starts.
- **3.4, 3.5, 3.6** the conversation external-events lane stream, its event
  records and sequence counter: pending follow-ups, steers and consent events
  and their exactly-once state.
- **3.15** the background job stream: a lost entry is never re-queued.
- **3.17** the Data Bus message stream: the publisher was already acknowledged.
- **3.20** the Data Bus dead-letter stream: the only record of failed
  deliveries, bounded by the retention policy in the
  [Data Bus](comm/data-bus-README.md) page.
- **4.19** the management effect ledger: no TTL; loss turns a replay into a
  duplicate external effect.
- **4.20e** admin passkey credential sets: no TTL and no other store.
- **B24, B25, B26** Connection Hub replay fences for identity-lookup,
  person-operation and Card-operation proofs: they stay in Redis in PostgreSQL
  mode, unlike the admission nonce (A5).
- **B10, B11** device-proof nonce and JTI: fenced against restores from an
  earlier Redis run, but not against a rollback inside the same run.

Only in one mode:

- **P3, P4, P5, A1 to A5** in Redis-source mode (see Authority mode).
- **4.1, 4.2** the bundle mapping and props, in legacy mode only; with a
  descriptor store they are caches.

Not decided by the code alone:

- **B1, B2, B3** OAuth code, CSRF and consent draft: retry-cost on loss, but a
  fence against a restored consumed record was not verified.
- **5.4** relay-done: losing it can re-execute a non-idempotent provider call.
- **2.35** the FAISS current-index pointer: the read path fails when it is
  missing, though the latest index file could be picked by hand.
- **C2** consent-granted conversation events written through the SDK lane.

## Declared but not written

These constants or defaults exist, but no code writes them at the commits above:
`REDIS.THROTTLING.STATS_KEY`, `REDIS.CIRCUIT_BREAKER.GLOBAL_STATS` and
`EVENTS_LOG`, `REDIS.SYNCHRONIZATION.LOCK` (`capacity:*`), the conversation
mailbox keys (the count key is read by admission and never written),
`CONFIG.BUNDLES.PRELOAD_LOCK_FMT`, `PRELOAD_BUNDLE_LOCK_FMT` and
`PRELOAD_BUNDLE_DONE_FMT`, `kdcube:cp:budget_policy:*` (only deleted), and
Connection Hub's default `connection-hub:one-time-state:*` prefix (both callers
pass their own). Nothing writes `delegated-access:automation:*`, and nothing in
these repositories constructs the `control-card:*` cache.

## Not covered

- Keys of the external proxy-login service (`REDIS_KEYPREFIX`
  `proxylogin:<TENANT>:<PROJECT>:`, `kdcube_cli/installer.py:4082-4086`).
- Dramatiq broker and result keys, which are library defaults.
- Keys that applications and bundles write themselves.
